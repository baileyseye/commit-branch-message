# Branch Commit Message

Плагин для IntelliJ IDEA, который автоматически подставляет имя текущей Git-ветки
в сообщение коммита.

## Как это выглядит

При открытии окна **Commit** поле сообщения заполняется так:

```text
feature/JIRA-123-login

|  ← курсор находится здесь, на строке тела коммита
```

То есть:

1. Первая строка — имя ветки (subject).
2. Вторая строка — обязательная пустая строка.
3. Третья строка — место для описания (body), туда сразу ставится каретка.

Именно такой формат Git использует для разделения заголовка и тела коммита.
Если ничего не дописывать, в коммит уйдёт только имя ветки: платформа
обрезает завершающие переводы строк.

## Поведение

- Работает в новом окне **Commit** и в классическом диалоге коммита.
- При смене ветки сообщение обновляется, если пользователь ещё не начал
  редактировать его (поле пустое или содержит только автоматически
  подставленное имя ветки).
- Если пользователь уже написал своё сообщение, плагин не затирает его.
- В состоянии detached HEAD (нет текущей ветки) сообщение не заполняется.
- Если в проекте несколько Git-репозиториев, берётся репозиторий в корне
  проекта, иначе первый найденный.

## Совместимость

- Минимальная версия: **IntelliJ IDEA 2026.2 (build 262)**.
- Проверено на установленной IDE: **IntelliJ IDEA 2026.2.4**
  (build `262.11879.100`).
- В `plugin.xml` указано `since-build="262"` без верхнего ограничения.
- Плагин написан на Java, байткод Java 21; IDEA 2026.2 работает на JBR 25,


## Установка

1. `Settings → Plugins`.
2. Шестерёнка → **Install Plugin from Disk...**
3. Выберите `build/distributions/commit-branch-message-1.0.0.zip`.
4. Перезапустите IDE.

Проверка: откройте Git-репозиторий, переключитесь на ветку
`feature/JIRA-123-login`, измените файл и откройте окно Commit (`Alt+0`).
Поле сообщения должно содержать имя ветки, пустую строку и каретку на
третьей строке.

## Как реализовано

- Регистрируется расширение `com.intellij.vcs.commitMessageProvider`
  (`BranchCommitMessageProvider`).
- Плагин реализует `DelayedCommitMessageProvider`: платформа отдаёт ему
  `CommitMessageUi` и `Disposable` при создании панели коммита.
- Начальное сообщение возвращается из `getCommitMessage` в виде
  `branch + "\n\n"`.
- Каретка ставится через `CommitMessage.getEditorField()` и
  `EditorTextField.setCaretPosition(...)`.
- Смена ветки отслеживается по `GitRepository.GIT_REPO_STATE_CHANGE`.
- Обновления UI выполняются в EDT через `ApplicationManager.invokeLater`.

### Про смещение каретки

В описании задачи было:

```kotlin
messageUi.component.caretPosition = branch.length + 1
```

При тексте `branch + "\n\n"` смещение `branch.length + 1` попадает **на
пустую строку** (перед вторым переводом строки). Если начать там печатать,
тело коммита окажется сразу под заголовком, и обязательная пустая строка
исчезнет. Поэтому плагин ставит каретку в конец документа
(`branch.length + 2` на Unix-переводах строк), то есть **после** пустой
строки. Это соответствует и текстовому требованию, и правилам Git.
